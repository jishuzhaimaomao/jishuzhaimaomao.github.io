# 项目全景：定位、版本与能力边界

## 1. FastBee 是什么

FastBee 把自己定位成“面向中小企业与个人开发者的轻量、易用、全栈物联网平台”。这句话拆开看就是它的产品策略：

- **轻量**：官方一键 Docker Compose 部署，单 JVM 进程即可承担 Web 服务、内置 MQTT Broker、规则引擎与业务存储；
- **易用**：产品/设备/物模型等概念贴近阿里云 IoT 等主流平台的建模思路，学习迁移成本低；
- **全栈**：后端、Web 管理端、移动端 App/小程序/H5、硬件 SDK 形成闭环，虽然移动端与硬件源码不在本仓库，但仓库为它们保留了完整接口。

与 EMQX、ThingsBoard、JetLinks 等竞品的差异点主要有：

| 对比维度 | FastBee | 备注 |
| --- | --- | --- |
| MQTT Broker | 内置 Netty Broker | 不额外依赖 EMQX，但也兼容 EMQX 扩展认证接口（代码中保留 auth/webhook v5 逻辑） |
| 产品建模 | 产品 → 物模型（属性/服务/事件） | 支持 JSON、数组、对象、MODBUS 寄存器等扩展字段 |
| 权限体系 | 若依 RBAC 多租户化 | 支持 admin/租户/普通用户多级隔离 |
| 时序数据 | MySQL 或 TDengine 等 | 通过统一接口 + 动态数据源切换 |
| 规则引擎 | LiteFlow + Groovy 脚本 | 数据流脚本 + 场景联动雏形 |
| 视频接入 | GB28181 SIP + ZLMediaKit | 开源版具备视频监控接入与播放 |
| 商用授权 | AGPL-3.0，商用可购买授权 | 开源版部分能力（如部分高级告警/联动）相对收敛 |

## 2. 版本与发布节奏

根 `pom.xml` 中 `fastbee.version` 为 `2.1.0`，对应仓库 README 的“开源版本”。技术底座版本也值得记录：

- Spring Boot `2.5.15`、Spring Security `5.7.12`、若依基座 `3.8.9`
- Netty（内置 Broker）
- MyBatis-Plus `3.5.3.1` + dynamic-datasource `4.3.1` + Druid
- Redis（连接、会话、物模型缓存、消息计数）
- LiteFlow `2.12.2`
- TDengine 驱动 3.x、IoTDB 1.x、InfluxDB

## 3. 仓库能力边界（哪些能做、哪些还没做）

通过阅读源码可以得到一个比 README 更“真实”的能力边界：

### 开源版已具备

1. **产品全生命周期管理**：分类、发布状态、认证方式、协议/传输类型、授权码、通用物模型模板；
2. **设备管理**：直连/网关/监控设备、激活/禁用/在线/离线状态、自动注册、分组、分享、运行状态、设备日志；
3. **物模型**：属性、功能（服务）、事件，支持 integer/decimal/string/bool/array/enum/object，支持监测、图表、历史、只读等标记；
4. **MQTT 接入**：自研 Broker 提供 TCP 1883 与 WebSocket 8083，支持认证、遗嘱、保留消息、QoS、订阅匹配；
5. **规则/数据流脚本**：设备上下行数据可在进入业务前用 LiteFlow 脚本改写 Topic 与载荷；
6. **数据中心**：属性/事件/功能日志查询、监测数据与历史曲线（依赖所选时序存储）；
7. **视频接入**：GB28181 设备注册、目录、实时预览、云台控制等（依赖 ZLMediaKit）；
8. **系统基座**：用户/角色/菜单/部门/岗位/字典/参数、操作日志、在线用户、定时任务、代码生成、Swagger 等若依能力；
9. **扩展登录**：JustAuth 三方登录、微信 App/小程序登录、OAuth2 client 配置（云云对接的前置管理）；
10. **部署**：Docker Compose 编排 MySQL、Redis、Java、Nginx、ZLMediaKit，SQL 覆盖 5 种数据库方言。

### 开源版要留意的不完整点

- **OTA 升级**：公共消息模型、`/upgrade/set`、`/upgrade/reply` Topic 与固件缓存均已定义，但 `IMqttMessagePublish#upGradeOTA` 的方法体为空，说明“远程固件升级”主流程尚未完成，测试时不要按完整功能验收。
- **场景联动/告警**：代码中保留了很多场景/告警概念与旧注释，核心场景（触发器、动作、定时、LiteFlow 动态链）已有实现基础，但部分告警推送逻辑被注释/收敛。
- **模拟设备与前端调试**：面向开发调试，不等于生产级设备仿真。
- **多节点集群**：设计上通过 Redis Channel 做消息桥接（`fastbee-mq/redischannel`），但订阅关系、保留消息、QoS 状态大量保存在**单机内存**，文档会专门提示扩展时的改造点。
- **硬件 SDK 与 App**：不在本仓库，接口需要与官方仓库对照联调。

## 4. 核心业务对象的一句话模型

```text
平台 = 产品（一种设备的“模板”）
     + 物模型（产品的数据语义：属性/服务/事件）
     + 设备（产品实例，携带唯一编号 serialNumber）
     + MQTT（设备的“嘴”与“耳”）
     + 规则/存储（让数据产生业务价值）
     + 租户与用户（把设备分给人管理）
```

在动手读代码之前，请先建立“产品未发布则设备不能认证、物模型是产品与设备之间数据的‘契约’”这两个心智模型。
